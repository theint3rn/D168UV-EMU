# D168UV emulator (Renode 1.17)

Runs the stock AnyTone D168UV V1.07 firmware (and the custom firmware, see `../cfw/README.md`) on an emulated
Artery AT32F403A board. Stock V1.07 boots to the main screen (VFO A/B, clock), keys, side keys and the channel
knob work.

```
python3 emu/run.py --seconds 15                        # stock image, headless; out/stock/lcd.png, state.txt
python3 emu/run.py --seconds 15 --then "0|lcd Press 13 200" --then "1|shot"
python3 emu/webui.py --launch orig                     # front panel, http://localhost:8894 (launch.json d168uv-orig)
python3 emu/build_extflash.py --base images/extflash_formatted.pages --no-icon   # rebuild NAND image
```
Boot to the main screen takes ~13 virtual s (~90 host s); afterwards the panel runs near real time.

## Firmware image
`../fw/d168uv_v107_08004000.bin` = flat image from `DL168UV_V1.07_20250606.CDD`: ER_IROM1 (0x1B0CC bytes) at
0x08004000, ER_IROM2 (0xC99DC bytes) at 0x08020000, gap filled with 0xFF (the .CDI lists both regions).
Bootloader 0x08000000-0x08003FFF is not in the package; the emulator starts at the app vector table
(`cpu VectorTableOffset 0x08004000`). Ghidra: `../ghidra/D168UV.gpr` (setup script `~/ghidra_scripts/D168UV_Setup.py`),
full decompile in `../decomp/src/fw_*.c`.

## Board model (`at32f403a.repl`, models/)
| Part | Wiring | Model |
|---|---|---|
| MCU | AT32F403A, Cortex-M4F, STM32F1 peripheral map, 1 MB flash, 224 KB SRAM | Renode F1 parts + `crm.py` (clock ready bits) |
| SysTick | 15 MHz (15 ticks/us in 0x20001808, LOAD 74999 = 5 ms) | `systickFrequency: 15000000` (Renode ignores CLKSOURCE) |
| LCD 128x160 portrait | 8080 bus PE7-PE14, WR PD15, CS PD14, D/C PD12 | `LcdKeypad.cs` (memory 160x128, `ppm2png.py` transposes) |
| Keypad | rows PE7-PE12 driven low, columns PC5 / PB1 / PB2 (scan FUN_0804339c) | `LcdKeypad.cs`, `lcd Layout "d168"` |
| Side keys | PTT PD0, PF1 PA13, PF2 PA14 (all active low; FUN_08092f08), ext PTT PA10 + detect PB8 | `BoardInputs168.cs` (`board Set "D0" false`) |
| Channel knob | encoder PC8/PC9, EXTI9_5 (IRQ23_Handler 0x0800679c) | `Knob168.cs` (`knob Turn 1`) |
| PA0 | high at boot = charge-only loop (FUN_08005444) | held low |
| SPI-NAND | Kioxia 2 Gbit 98 CB/EB, 2 KB pages, 64 pages/block; CS PE2, SCK PB11, MOSI PB10, MISO PA15 (x2 read: PA15+PB10) | `SpiNand168.cs` |
| RF transceiver | 3-wire SCK PB3, SDA PB4, CS PB5; self test reg 0x57 = 0xA888 | `RfTransceiver.cs` (D890 model), read hook FUN_0807bca8 |
| SCT3288 baseband | SPI2 (F1 regs), CS PB12, ready PD11, frame pending PD6; `84 A9 61` frames, MCU reads by clocking 0xA5 | `Baseband168.cs`, log out/<run>/baseband.log |
| I2C (bit-bang) | SDA PB6, SCL PB7: FM broadcast receiver 0x10 (RDA5807-style), accelerometer 0x19 (LIS2DW12, WHO_AM_I 0x0F = 0x44; man down polls STATUS 0x27 / SIXD_SRC 0x3A) | `I2cBus168.cs` (`i2c Fall`, `i2c Upright`, `i2c SixD 0x41`, `i2c Orientation`) |
| VOX detect | PD3 input (low = voice; RF chip VOX output, stock poll 0x08099B4C); idle level D3=1 in `at32f403a.repl`; `board Set "D3" false` = voice. The RF model keys TX on reg 0x56 = 2 / reg 0x30 = 0x5F64 only (reg 0x52 switch 3 is the VOX switch here) | `BoardInputs168.cs`, `RfTransceiver.cs` |
| RTC | F1 seconds counter, IRQ 3 | `Rtc168.cs` |
| BT module | UART4, AT commands `AT+...\r\n`, replies `+VER:` `+PIN:` `+DNAME:` `+CONN:` `+SCAN:` `OK` (parser FUN_0800b024, table 0x0801c548) | `Bt168.cs` (`bt Devices "MAC,name;..."`, `bt Present false`, `bt Line "..."`), log out/<run>/bt.log |
| GPS | USART2 NMEA (IRQ38 -> FUN_0803a11c -> FUN_0807289c), $GNRMC/$GPRMC/$GPGGA/$GPGSV | `Gps168.cs` (copy of the D890 model: `gps Position lat lon alt`, `gps Fix false`) |
| ADC1 battery | PC1 = ch11, scan + DMA1 ch1 -> 0x200017CC, V*100 = (raw*0x528>>12)+cal-100 | `Analog168.cs` via `stock168.repl` (stock only; cfw168.repl has its own): `analog Battery 6.0` |

## Images

`run.py` picks the NAND image: `--nand FILE`, else `images/extflash.pages` if present, else `images/synth.pages`
(generated by `make_nand.py` when missing). Custom firmware (`--cfw`) runs need only our own files.

| File | Content | Source | Needed for |
|---|---|---|---|
| `images/synth.pages` | synthetic NAND: block-0 bad-block table + `0x1FF00` "CHECKING BLOCK FOR VALID.", `0x3E0000` 10-byte check value (0x55..0x5E, compared by FUN_08028760), `0x02FE0000` "CHECKING DATA FOR D868S!", zeroed settings block `0x02500000` (stock then gets past its boot loop, loads the calibration and stops at "Program Error", no codeplug), default RF calibration block `0x02F60000` (`cfw/drivers/cal_default.c`, made by `cfw/tools/make_cal_default.py`; marker at +0x1FFFC). No channels (cfw168 does not read the stock NAND channel layout) | `make_nand.py` (ours) | default when `extflash.pages` is absent |
| `images/bootstub168.*`, `images/idle_*.bin` | bootloader stand-in, idle WFI patch | ours | cfw / stock speedup |
| `images/extflash.pages`, `images/extflash_formatted.pages` | stock first-boot format + ICON fonts/logo | `build_extflash.py` from **your own** AnyTone package (ICON V1.34 .CDI/.CDD); `extflash_formatted.pages` = the stock firmware's own first-boot format saved with `nand SaveOverlay` | stock runs with text and fonts |
| `../fw/d168uv_v107_08004000.bin` | stock firmware, flat image (see "Firmware image") | **your own** AnyTone package | stock runs |

AnyTone files are not part of the published repo. A stock run without the firmware image stops with an error naming
it; without `extflash.pages` the stock firmware runs on `synth.pages` and stops at "Program Error" (no codeplug, no ICON data).

`D890UV_src/cfw/tools/apc_test168.py` passes on `synth.pages` (2026-11-23, all 4 levels) when its stock boot is 15 s:
on `synth.pages` the stock firmware copies the calibration to RAM later than on `extflash.pages` (6 s is too short).

```sh
python3 emu/make_nand.py                                   # -> images/synth.pages
python3 emu/run.py --cfw --elf cfw/build/cfw168.elf --nand emu/images/synth.pages --seconds 4
```

## NAND contents
`images/extflash.pages` = `images/extflash_formatted.pages` (firmware's own first-boot format, saved with
`nand SaveOverlay`) + ICON package V1.34 (fonts, logo at 0x20000-0x614C00). Markers the firmware checks:
block-0 bad-block table + 0x1FF00 "CHECKING BLOCK FOR VALID." (else it erases/tests every block), 0x3E0000
`lcdfront_check.bin` (else "UPDATE MODE"), 0x02FE0000 "CHECKING DATA FOR D868S!" (else data areas re-initialised).

Patch a NAND byte before boot (codeplug setting): `nand Poke 0x2500024 1` (in `--extra`, runs before the CPU starts).

## Man down (stock V1.07)
No radio menu item; it is a codeplug setting. The accelerometer INT1 pin is not used: CTRL4 = 0x80 routes 6D to
INT1, but the firmware only polls over I2C.
* Settings block NAND 0x02500000 (A copy; B = +0x20000, 0xF0 bytes -> RAM 0x20009BC8): +0x24 man down on/off (stock CSV `FailAlarm`, .rdt 0x71 = CPS Alarm Setting "Man Down"),
  +0x4F wait in seconds (stock CSV `ManDownWait`, .rdt 0x93).
* Poll at 0x08028A20 (task code, every 2 ticks of 0x200018C8): STATUS 0x27 bit0 (DRDY), then SIXD_SRC 0x3A bit0
  (XL = X axis below -60 deg; set while the radio stands upright). XL clear for 30 polls -> flag 0x200018BE = 1 ->
  FUN_08031e78(1): countdown 0x200018C6 = wait + 1 s (RTC IRQ3 counts down). XL set again -> FUN_08031e78(0) cancels.
  Countdown reaches 1 -> FUN_08031ef8 -> emergency alarm (FUN_0802f060: alarm state 0x20000820 = 1, revert channel).
* Alarm state machine 0x0802503C (state 0x20000820, 0..6). Alarm Setting block NAND 0x024C1400 (0x1C bytes ->
  0x2000282E): type byte analog +0x00, digital +0x0A (0 = local alarm only: "Alarming" popup, state 2/6; 1..3 = TX
  alarm: state 3 keys TX ~1 s with baseband cmds 0x3E + 0x43, then states 4/5), +0x03/+0x0D wait x 10 ticks,
  +0x06/+0x0E revert channel, +0x08/+0x10 use current channel, +0x09/+0x11 cycles (0x20000827).
* Test:
  ```
  python3 emu/run.py --seconds 10 --extra "nand Poke 0x2500024 1" --then "0|i2c Fall" --then "3|shot" --then "0|i2c Upright" --then "3|shot"
  # TX alarm (digital channel): also --extra "nand Poke 0x24C140A 1"; watch `rf0 Transmitting`
  ```
  Result: "Alarming" popup ~0.5 s after the fall (wait 0); `i2c Upright` clears it. With type 1 the RF chip
  transmits for about 1 s after the alarm starts. With wait 5 (`nand Poke 0x250004F 5`) the countdown runs 6..2 with
  no screen change, then the alarm starts (~5 s after the fall).

## Speedups (default; `--exact` turns them off)
* delay_us FUN_08013d30 polls SysTick: a CPU hook skips virtual time in 25 ms slices (one big SkipTime stalls Renode).
* Idle task loop 0x0800abe2: its call to the idle hook at 0x0800abf8 goes to `images/idle_cave.bin` at 0x0801FF00
  (`wfi; b.w 0x08009e42`, unused gap after ER_IROM1).
* Accelerometer register access FUN_0805aa04 / FUN_0805aaa4 served from the I2C model's register array.

## Error screens seen while bringing it up (and their cause)
* "Flash Error!! Check&Change": NAND ID wrong/missing (FUN_080055e8 expects 98 CB or 98 EB).
* "UPDATE MODE": 0x3E0000 check string missing, or PD0 + PA14 held low at boot (key combo).
* "Rf Mcu Error / Check Hardware": RF chip reg 0x57 read-back failed (FUN_080290b8).
* Logo forever: baseband not answering (FUN_080865ac waits up to 1000 x 50 ms), or I2C device not ACKing.
* Keys ignored: SysTick too fast (backlight timer expired at once; first key only wakes the backlight).

## Menu crawl (stock V1.07)
Text hooks (GBK byte strings): `FUN_0804f4d4(x, y, ch)` one ASCII glyph, `FUN_0804fc4c(x, y, char *gbk)` one GBK glyph,
`FUN_08051328(x0, y0, x1, y1, tx, ty, char *s, scroll)` list-row text (own glyph loop). `FUN_08050e30` is the plain
string renderer (it uses the two glyph functions). Main screen = soft keys MENU / LIST; Exit on it opens the TG list.
```
python3 emu/crawl_all.py --jobs 4 --depth 5          # one fresh emulator per main-menu item -> out/crawl/item_NN/
python3 emu/crawl.py --port 1335 --only 11          # one item on a running run.py --serve 1335
python3 emu/crawl_report.py out/crawl               # out/crawl/tree.md (+ screenshots), summary for MENUS.md
```
Option lists (Select shows a value popup) are read by moving Down after one probe Select (the probe selects the
current value; each main item runs in a fresh emulator). Lists open on the current value; the highlighted row is found
from the blue bar in the screenshot. Values of `NO_SELECT` lists (Language) are read, never selected. Settings takes
~2 h (2400 key presses), the whole crawl ~3 h with 4 jobs. `ctl.py` broker retries the monitor connect (busy host). Results: `MENUS.md`,
comparison with the stock CPS and the cfw UI: `COMPARE_MENUS_CPS.md`.

## cfw pre-flash test support (2026-11-23)

- cfw runs (`run.py --elf`): `images/bootstub168.bin` (source `bootstub168.S`) at 0x08000000 and the 0x0 alias, a
  stand-in for the stock bootloader: a system reset (cfw fault handler) restarts from 0x0 and lands in the app again.
- `models/crm.py`: write 1 to 0x400213FC = HEXT never stable (clock-failure test).
- `models/BoardInputs168.cs`: levels set with `board Set` (a held key) survive a soft reset.

## Repository layout

This is one of six repositories: D890UV-CFW, D168UV-CFW, D890UV-CFW-CPS, D168UV-CFW-CPS, D890UV-EMU, D168UV-EMU.
The build and test scripts expect them side by side in this layout:

```
work/D890UV/D890UV_src/cfw       <- D890UV-CFW
work/D890UV/D890UV_src/cfw_cps   <- D890UV-CFW-CPS (or D168UV-CFW-CPS)
work/D890UV/D890UV_src/emu       <- D890UV-EMU
work/D168UV/cfw                  <- D168UV-CFW
work/D168UV/emu                  <- D168UV-EMU
```

No firmware, flash images or programming files from the radio maker are included. The emulators build their own
flash images (`emu/make_nand.py` -> `images/synth.pages`); running the original radio firmware in the emulator needs
files made from your own radio package (see the emulator README). Flashing a real radio (CFW repositories): `docs/HARDWARE.md`,
`docs/CALIBRATION.md` and `docs/PREFLASH_AUDIT.md`.
